# Contributing to Volt Forge Studio

Thank you for your interest in improving Volt Forge Studio. Contributions should be focused, respectful, and easy to review.

## Before You Start

1. Search existing issues and pull requests to avoid duplicate work.
2. Open an issue for significant changes so the approach can be discussed first.
3. Never include credentials, private data, generated artifacts, or unrelated changes.
4. Follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Development Workflow

1. Fork the repository and create a branch from the default branch.
2. Use a clear branch name, such as `feat/project-gallery` or `fix/mobile-navigation`.
3. Make small, focused commits with descriptive messages.
4. Add or update tests and documentation when applicable.
5. Run the project's formatting, linting, tests, and build checks once those commands are documented.
6. Open a pull request using the provided template.

## Pull Request Guidelines

- Explain the problem and the chosen solution.
- Link related issues using `Closes #123` when appropriate.
- Include screenshots or recordings for visual changes.
- Call out breaking changes, migrations, and follow-up work.
- Keep each pull request limited to one logical change.

Maintainers may request revisions before merging. Submission of a contribution does not guarantee acceptance.

## Reporting Bugs and Requesting Features

Use the appropriate GitHub issue template and provide enough context for someone else to reproduce or evaluate the request. Security vulnerabilities must be reported privately according to [SECURITY.md](SECURITY.md).
